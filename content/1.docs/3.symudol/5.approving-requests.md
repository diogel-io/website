This page describes Symudol 1.0.0.

## How apps ask Symudol

Nostr apps on your phone talk to Symudol through NIP-55, the Android signer standard. There are two ways a request arrives.

### With your review

The app opens Symudol with a `nostrsigner:` request. Symudol comes to the front, switches to the **Requests** tab and shows the request. When you approve or reject, Symudol sends the answer back to the app.

If the vault is locked, you unlock first. See [A request is waiting](/docs/symudol/vault#a-request-is-waiting).

If you do not decide within 5 minutes, Symudol tells the app the request timed out.

### In the background

An app can also ask in the background, without opening Symudol. Symudol answers only when you have already remembered a decision that covers the request, and:

- the request comes from the same app you remembered it for, checked by its package name and signing certificate, and
- the request is for the active identity.

Then:

- A remembered decision to share your public key, or a remembered rejection, is answered even while the vault is locked. Your public key is public, and a rejection reveals nothing.
- Signing, encrypting and decrypting are answered only while the vault is unlocked.

In every other case, Symudol gives no background answer and the app opens Symudol so you can review the request. This also happens if Symudol cannot sign quickly enough, if the request is for another account, or if a `sign_event` request has no valid event kind.

### From a website

A website on your phone can also send a `nostrsigner:` request through the browser. Symudol shows it for review in the same way. The result goes back through the website's return link or, if there is none, is copied to the clipboard.

A copied result is marked sensitive, so Android hides it in clipboard previews. Symudol does not clear it from the clipboard afterwards. After you paste a decrypted message, clear the clipboard or copy something else.

Decisions for browser requests cannot be remembered, because Symudol cannot tell which website sent them.

::note
Some apps only look for one specific signer app and do not find other signers. Those apps cannot use Symudol until they support standard NIP-55 signer discovery.
::

## Supported requests

| Request | What it does |
|---|---|
| `get_public_key` | Shares the active identity's public key. |
| `sign_event` | Signs a Nostr event with the active identity. |
| `sign_message` | Signs a plain message. |
| `nip04_encrypt` / `nip04_decrypt` | Encrypts or decrypts a NIP-04 message. |
| `nip44_encrypt` / `nip44_decrypt` | Encrypts or decrypts a NIP-44 message. |
| `decrypt_zap_event` | Decrypts a zap event. |

Symudol refuses a `sign_message` request whose text is the form an event takes when it is signed: a JSON list of six items that starts with `0`, as NIP-01 defines. Signing that text would give a valid signature for an event, so this stops an app from using a message request to get an event signed without showing it as one. The app is told the request was refused. Other text, including an event written as a JSON object, is signed as a plain message.

Symudol reviews one request at a time. If a second request arrives while you are reviewing one, Symudol refuses it with "Symudol is already reviewing another NIP-55 request", unless you have already remembered a decision that covers it. If the second request comes from the same app as the one on screen, it may wait for your decision instead. It is then answered if the decision you remember covers it, and refused otherwise.

## The Approval Request screen

![An Approval Request for a text note](/img/screenshots/symudol/approval.png)

From top to bottom, the screen shows:

### Source warning

If Android could not confirm which app sent the request, you see **Unknown Provenance**: "The requesting application is not in your verified list. Exercise caution."

A request is verified when Android reports both the app that sent it and its signing certificate. Only verified apps can have decisions remembered.

### The requesting app

The app's name and icon. A green check mark means Android told Symudol which installed app sent the request, and that app's signing certificate. It does not prove the app comes from the developer its name suggests: an app can copy a familiar name and icon and still get a check mark. If Android did not say which app it is, you see **Unknown Android caller**.

Some well-known Nostr apps, such as Amethyst, also show a short description. The description comes from the app's package name, so it is not proof of who sent the request either. Install Nostr apps only from sources you trust.

### What is being asked

**Signing an event.** You see the event type, such as **Text note**, and a preview of its content. Symudol names the event type from its own list of event kinds.

Event types that can change something important show a **Risk note**. For example:

- Profile (kind 0): "This can change your public profile metadata."
- Contact list (kind 3): "This can replace your contact list."
- Deletion request (kind 5): "This asks relays and clients to delete or hide referenced events. Deletion is not guaranteed across all relays."
- Relay list (kind 10002): "This can update your public relay list metadata."
- Mute list (kind 10000): "This can replace your mute list."
- Client authentication (kind 22242): "Client authentication proves control of this key to a service."
- Zap requests (kind 9734) carry a note about payments.

If Symudol does not know the event kind, it always shows a risk note for the kind's range:

- Replaceable kinds: "This is a replaceable event. Signing it can overwrite prior state for this key on participating relays. Review the requesting app and content before signing."
- Ephemeral kinds: "This is an ephemeral event. Relays are not expected to store it, but signing still authorises the content under your key."
- Addressable kinds: "This is an addressable event identified by kind, pubkey, and d tag. Signing it can create or replace stored state. Review the d tag and requesting app before signing."
- A missing or invalid kind: "The event kind is missing or invalid. Do not sign this request."
- Any other kind: "This kind is not yet in Symudol's event-kind registry. Review the requesting app, content, and tags before signing."

**Sharing your public key.** You see **Connect to signer**, or **Permissions requested** with the list of permissions the app asked for. If the app listed none, you see "No additional permissions were declared."

If the app asked to sign any kind of event, you see: "This app asked to sign any kind of event. That is not remembered: you will be asked for each one."

**Signing a message.** You see "Signs this exact text with your key" and the full **MESSAGE**.

**Encrypting or decrypting.** You see the operation, such as **NIP-44 Decrypt**. Decryption is marked "Sensitive decrypt operation — review carefully". You also see the **PEER PUBLIC KEY** and a **PAYLOAD PREVIEW**.

### Show details

Tap **Show details** to see more, and **Hide details** to close it.

- For an event: the **NIP-55 METHOD**, the **PERMISSION IF REMEMBERED**, the **CONTENT**, the **CREATED AT** time, the **TAGS**, and the full event as JSON.
- For a public key request: the **REQUESTED PERMISSIONS**, and under **PUBLIC KEY** the exact key the app will receive.

![Request details for a text note](/img/screenshots/symudol/nip55-request.png)

### Remember this decision

When Symudol can remember a decision for this app, you can choose:

- **Just once**: "This decision applies to this single request only."
- **8 hours**: "Requests from this app will be auto-approved for 8 hours."
- **Always**: "All future requests from this app will be auto-approved."

This choice is not offered:

- For browser requests.
- For apps Android did not verify.
- When the request is for a different account than the active one.
- When a `sign_event` request has no valid event kind.

### The buttons

- **Reject** refuses the request.
- The approve button depends on the request:
  - **Sign event** signs the event.
  - **Share public key** shares your public key.
  - **Sign** signs a message.
  - **Encrypt** or **Decrypt** runs the operation.

After signing, you see **Event signed**: "The event was signed locally with your selected identity. It has not been published by Symudol." Symudol never publishes events. The app that asked does that.

If signing fails, tap **Dismiss failed request** to clear it.

When there is nothing to review, the Requests tab shows **No active requests**. If you have no identity yet, it shows **Create an identity first**.

## What remembering covers

A remembered decision applies to one app, checked by its package name and signing certificate, the active identity, and one kind of request:

- **Signing**: events of the same kind only. For example, approving a text note covers text notes, not profile updates. Signing any kind of event is never remembered.
- **Signing a message**: any message from that app. A remembered **Sign** decision lets the app sign different messages without asking you again. Symudol still refuses messages that are really events (see [Supported requests](#supported-requests)).
- **Encrypting**: a decision on the Approval Request screen covers messages to the same peer.
- **Decrypting**: messages from any peer. NIP-04 and NIP-44 are remembered separately. A remembered decrypt also covers zap events, and you can remember `decrypt_zap_event` on its own.
- **Sharing your public key**: if the app listed other permissions when it asked for your public key, those are remembered too.

::warning
Permissions an app lists when it connects are broader than decisions you make one request at a time. A remembered encrypt or decrypt permission from that list covers any peer. Read the **Permissions requested** list before you choose **8 hours** or **Always**.
::

### Client authentication

Some apps sign a client authentication event (kind 22242) to sign in to a relay. A permission the app lists when it connects can be limited to one relay, shown as "Sign kind 22242 for" followed by the relay. A decision you make on the Approval Request screen covers every relay.

### How long a decision lasts

**8 hours** ends after 8 hours. **Always** has no end date.

This applies to rejections too. If you reject with **8 hours** selected, requests of that kind from that app are refused without asking for the next 8 hours. With **Always**, they are refused until you revoke the decision.

## Trusted Nostr apps

To review remembered decisions, open [Settings](/docs/symudol/settings), then **Trusted Nostr apps**.

Each app shows:

- Its name and Android package name.
- The identity the decisions belong to.
- When it was last used.
- Each remembered decision, such as "Allowed • Sign kind 1" or **Rejected**, with its status and when it was created.

A decision's status is **No expiry**, **Expires** with a date, or **Expired**. A decision saved without the app's signing certificate shows **Not tied to a signing certificate: asks each time**, and Symudol asks you again.

To remove decisions:

- Tap the bin icon (**Revoke permission**) next to one decision.
- Tap **Revoke app**, then confirm **Revoke app permissions?**, to remove every decision for that app.
- Tap **Revoke all** at the top, then confirm **Revoke all trusted apps?**, to remove every remembered decision. Future requests will ask again.

If nothing is remembered, you see "No remembered NIP-55 app permissions yet. Approvals you remember from verified native app requests will appear here."
