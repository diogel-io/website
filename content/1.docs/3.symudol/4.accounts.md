This page describes Symudol 1.0.0.

## The Accounts screen

**Accounts** is the first tab after you unlock. It lists the Nostr identities in your vault under "Manage your Nostr identities".

![The Accounts screen with one active identity](/img/screenshots/symudol/accounts.png)

Each identity shows:

- Its profile picture, once you [load its profile](#load-a-profile).
- Its display name, or **Unnamed Identity** if you did not give one.
- A shortened `npub...` public key.

Each identity also has buttons:

- **Edit profile** and **Relays**, on the active identity only. See [Edit your profile](#edit-your-profile) and [Your relay list](#your-relay-list-nip-65).
- **Export private key**. See [Export a private key](#export-a-private-key).
- **Load profile**. See [Load a profile](#load-a-profile).

If the vault is empty, you see **No Identities Found** and "Create or import your first Nostr identity to get started." You can also tap **Restore from a backup** to bring back identities from a backup file. See [Restore from a backup](/docs/symudol/vault#restore-from-a-backup).

## Create a new identity

Use this if you are new to Nostr or want a fresh identity.

1. Tap **Add New**.
2. In **Create New Identity**, enter a **Display Name**. This is optional.
3. Tap **Create**.

Symudol generates a new key pair on the phone and shows "Identity created successfully".

The display name is a local label. It does not change your public Nostr profile. To change that, see [Edit your profile](#edit-your-profile).

Make a [backup](/docs/symudol/vault#back-up-your-vault) after you create an identity. Until you do, the key exists only on this phone.

## Import an existing key

Use this if you already have a Nostr identity.

1. Tap **Import Private Key**.
2. Read the warning and tap **I Understand**. Make sure your screen is not being shared or recorded.
3. In **Enter Private Key**, paste your key. Symudol accepts an `nsec1...` key or a 64-character hex key.
4. Optionally, enter a **Display Name**.
5. Tap **Continue**.
6. Tap **Confirm & Import**.

The key is hidden as you type. Tap the eye icon to show it. Symudol asks your keyboard not to learn or suggest what you type in these fields.

When it works, you see "Identity imported successfully".

### Import errors

- **Private key is required**: the key field is empty.
- **Invalid nsec key format**: the `nsec1...` key is not valid. Check you copied all of it.
- **Invalid private key format**: the key is neither a valid `nsec` nor 64 hex characters.
- **This identity already exists in your vault.**: that key is already stored.

## The active identity

Symudol signs with one identity at a time: the active identity.

- The first identity you add becomes active automatically.
- The active identity has a highlighted border and a check mark.
- To switch, tap another identity in the list.

Every request from another app uses the active identity. Check it before you approve anything. If an app asks for a different account than the active one, the request can be refused with "Requested account does not match active identity." Switch accounts and try again from the app.

Profile and relay-list changes are also signed with the active identity, so **Edit profile** and **Relays** appear only on it.

## Load a profile

Symudol does not look up profiles on its own. Nothing is fetched until you ask.

1. Tap **Load profile** on an identity.
2. Read **Load profile from relays?**. It names the relays Symudol will ask. They will see this public key and your IP address.
3. Tap **Load profile**.

You see "Profile loaded", and the identity shows its profile picture. If the relays cannot be reached, you see "Couldn't reach the relays".

If none of the relays has a profile for the identity, you see **No profile found** with the relays it asked. The identity keeps a plain person icon.

A loaded profile stays in memory until you close Symudol. It is never saved on the phone, so Symudol asks again next time you open it. See [Which relays Symudol asks](#which-relays-symudol-asks).

## Edit your profile

You can edit and publish the Nostr profile of the active identity. Other Nostr apps show this profile.

1. Tap **Edit profile** on the active identity.
2. Confirm **Load profile from relays?**. Symudol loads the newest profile first, so you edit what is already published.
3. Change the fields you want.
4. Tap **Save**.
5. Read **Sign and publish?**. It names the identity and the relays the profile goes to. Anyone can read a published profile.
6. Tap **Sign and publish**.

The fields are:

- **Name**, **Display name**, **About** and **Website**.
- **Picture URL** and **Banner URL**. See [Upload a picture or banner](#upload-a-picture-or-banner).
- **NIP-05 identifier**. See [Verify your NIP-05 identifier](#verify-your-nip-05-identifier).
- **Lightning address**, for receiving zaps.
- **Birthday**, as **Year**, **Month** and **Day**. All are optional.
- **This is a bot**, which "Marks the profile as automated (NIP-24)."

A preview card at the top shows how the profile looks. Images in it stay hidden until you tap **Show images**.

If a field is not valid, Symudol highlights it and shows "Fix the highlighted fields first." For example:

- Website, picture and banner addresses must start with `https://`.
- A lightning address looks like `name@domain.com`.

### After you publish

**Profile published** shows how many relays accepted the profile. Each relay shows **Accepted**, **Rejected** or **No answer**, with the relay's message if it sent one.

### Your other profile fields are kept

When you save, Symudol reads the newest profile again and changes only the fields you edited. Fields set in other apps that Symudol does not show are kept.

If no relay answers, Symudol does not save: "No relay answered, so saving could drop fields set in other apps. Your profile has not changed. Try again."

### If no profile is found

If no relay has a profile for the identity, you see **No profile found** and a warning:

> If this identity has a profile on other relays, creating a new one here may replace it in apps that read these relays.

Tap **Create a new profile** only if this identity has no profile anywhere, or you are happy to replace it.

### Save errors

- "No relay accepted the update, so your profile has not changed. Try again."
- "This identity is no longer the active one. Make it active to save its profile."
- "Symudol is locked. Unlock it, then save again."

If you leave with unsaved changes, Symudol asks **Discard changes?**. Tap **Keep editing** to go back.

## Upload a picture or banner

Next to **Picture URL** and **Banner URL** there is an upload button.

1. Tap the upload button.
2. Choose **Choose from photos**, or **Take a photo** if the phone has a camera.
3. Read **Upload to** followed by the server name, and tap **Upload**.
4. Tap **Save** on the profile to publish the new image.

You see "Image uploaded. Save to publish it on your profile."

::warning
An uploaded image is public. Anyone with the link can see it, even if you do not save the profile.
::

Before uploading, Symudol re-encodes the image as a new JPEG. This removes its location, camera details and other hidden data.

- A picture is resized to at most 1024 pixels on its longest side, and a banner to 1920 pixels.
- Transparent areas become white, and an animated image keeps only its first frame.
- Images over 25 MB are refused: "That image is too large. Choose one under 25 MB."

Symudol uses the system photo picker and camera, so it needs no storage or camera permission.

Images go to the identity's own Blossom media server, if its profile lists one. Otherwise they go to the server in Settings, which is `https://blossom.primal.net` by default.

## Verify your NIP-05 identifier

A NIP-05 identifier looks like an email address, such as `name@example.com`. It shows that a website lists your public key.

1. In **Edit profile**, enter your identifier in **NIP-05 identifier**.
2. Tap **Verify**.

Symudol checks only when you tap **Verify**. If it works, you see "Verified:" followed by the domain, and "lists this identity's public key." If you change the identifier, the result is cleared.

If it fails, Symudol says why:

- The domain does not list this name.
- The domain lists this name for a different public key.
- The domain's answer is not a valid NIP-05 response.
- The domain could not be reached.

Symudol does not check identifiers on IP addresses or local network names.

## Your relay list (NIP-65)

Your relay list tells other Nostr apps where to find your posts and where to send you replies and mentions.

1. Tap **Relays** on the active identity.
2. Confirm **Load relays from the network?**. Symudol loads the newest relay list first.
3. Change the list.
4. Tap **Save**, then **Sign and publish**.

**Relays published** shows how many relays accepted the list.

Each relay has two chips:

- **Write**: other apps read your posts from these relays.
- **Read**: other apps look for replies and mentions on these relays.

A relay must keep at least one of the two.

To add a relay, enter it in **Add a relay** and tap **Add relay**. If you leave out `wss://`, Symudol adds it. To remove a relay, tap the remove button next to it.

- "That isn't a relay address (wss://…)." means the address is not a relay.
- "That relay is already listed." means it is in the list already.
- "Keep at least one relay, or other apps can’t find your events." means you removed every relay.

NIP-65 suggests 2 to 4 read relays and 2 to 4 write relays. Symudol warns you if your list is longer. It looks up profiles on your first 8 write relays only.

If no relay has a list for the identity, you see **No relay list found**. Tap **Create a relay list** only if this identity has no relay list anywhere, or you are happy to replace it.

If no relay answers when you save, Symudol does not save: "No relay answered, so saving could overwrite a list you haven't seen. Your relays have not changed. Try again."

## Which relays Symudol asks

When you load or edit a profile or relay list, Symudol asks two sets of relays.

**Profile relays.** Profiles are read from and published to these.

- `wss://relay.damus.io`
- `wss://nos.lol`
- `wss://relay.primal.net`

**Indexer relays.** These collect profiles and relay lists from across the network.

- `wss://purplepag.es`
- `wss://profiles.nostr1.com`
- `wss://relay.nos.social`

Symudol also asks the identity's own write relays, up to 8, from its relay list. It uses the newest answer.

Your profile is published to the profile relays and the identity's write relays. Indexer relays are sent your relay list when you save it, but never your profile.

Every relay Symudol asks sees the identity's public key and your IP address.

To change the relays or the media server, open [Settings](/docs/symudol/settings) and tap **Profile relays and media server**. Wiping the vault resets them to these defaults.

## Export a private key

You can show and copy an identity's private key (`nsec`), for example to use it in another signer.

::warning
Anyone with this private key controls the identity, and it can't be changed or revoked. Never paste it into a website or app you don't trust. To keep a safe copy, use [Back up your vault](/docs/symudol/vault#back-up-your-vault) instead, which encrypts the key with a passphrase.
::

1. Tap **Export private key** on the identity.
2. Read the warning and tap **I understand, continue**.
3. Enter your PIN and tap **Continue**.
4. Under **Private key (nsec)**, the key is hidden. Tap **Show** to see it, or **Copy** to copy it.

Wrong PINs here count toward the [wait after too many wrong PINs](/docs/symudol/vault#too-many-wrong-pins).

Symudol protects the key while it is on screen:

- You cannot select the key text. **Copy** is the only way to copy it.
- The copy is marked sensitive, so Android hides it in clipboard previews.
- The clipboard is cleared after 60 seconds: "Private key copied. The clipboard clears in 60 seconds."
- Screenshots and screen recording are blocked.
- If the vault locks, the screen closes.

## Rename or remove an identity

Symudol 1.0.0 cannot rename an identity or remove a single identity.

- The display name is set when you create or import the identity.
- To remove every identity, [wipe the vault](/docs/symudol/vault#wipe-the-vault). Make a backup or export the keys you want to keep first.
