title: Relay Management

Relays are servers that store and transmit Nostr events. Your relay choices affect how well other clients can find your events and how reliably you can publish.

## What Relay Management is for

Use Relay Management to:

- view relays for the active account
- add relay URLs
- choose read/write behavior
- browse relay catalog entries
- publish relay metadata
- choose the Direct Message Relays where people send you private messages
- choose the Profile Search Relays used to find Nostr profiles
- keep the relay list small and useful

## What relays do

Nostr does not use one central server. Instead, clients publish and fetch events from relays.

A relay can be used for:

- **read** — clients fetch your events from it
- **write** — clients publish your events to it
- **read and write** — both

## Relay URLs

Relay URLs usually start with:

```text
wss://
```

Some local or test relays may use:

```text
ws://
```

For normal internet use, prefer `wss://`.

## Read relays

Read relays tell other clients where to find events for your account.

Choose read relays that are stable and commonly reachable.

## Write relays

Write relays are where Porwr and other clients can publish events.

Choose write relays that accept your events reliably.

## NIP-65 relay metadata

NIP-65 defines a relay list metadata event, often kind `10002`.

Publishing relay metadata helps other clients know where to read from and write to for your account.

When you save relay settings in Porwr, it signs and publishes relay metadata for the active identity.

## Recommended relay count

Keep relay lists focused.

A practical starting point is:

- 2-4 read relays
- 2-4 write relays
- overlap is fine when a relay is good for both.

Too many relays can slow publishing and create noise. Too few can reduce availability.

## Relay Browser

The Relay Browser helps you discover relays.

It can support:

- searching by name
- searching by hostname
- searching by URL
- filtering for search-capable relays
- refreshing the relay catalog
- changing results per page.

Use the browser as a discovery tool, not as an automatic recommendation engine. You still need to choose relays intentionally.

## Direct Message Relays

Direct Message Relays are where other people send you private messages (NIP-17). Porwr publishes them as a
kind `10050` relay list so other clients know where to reach you. [Messaging](/docs/porwr/messaging) and
Support depend on them.

![The Direct Message Relays card](/img/screenshots/porwr/relay-dm-relays.png)

NIP-17 recommends 1 to 3 relays. Porwr warns you if you add more than 3.

### Relays that keep messages

Some relays accept private messages but do not keep them, so nothing sent there reaches you. `relay.damus.io`
is one of them.

When you save, Porwr checks each relay by sending it a test message from a throwaway key, and marks it
**Keeps messages**, **Drops messages**, or **Couldn't check**.

- If no relay keeps messages, Porwr does not publish the list. Add a relay that keeps them and save again.
- If only some relays drop messages, Porwr asks before you **Publish anyway**.

Inbox relays that use NIP-42 authentication work best, because they show your messages only to you.

## Profile Search Relays

Profile Search Relays are used when you search for a Nostr profile by name, npub, hex public key, or NIP-05
identifier, for example when adding a contact or starting a conversation. They apply to all accounts in the
vault. In earlier versions this setting was in **Settings**.

![The Profile Search Relays card, with the default relays](/img/screenshots/porwr/relay-profile-search.png)

- Add relays with the same relay search as the relay list.
- Choose **Save** to keep your changes.
- Saving an empty list restores the default relays.

Search works best with relays that support NIP-50 search. Use **Search-capable only (NIP-50)** in the Relay
Browser to find them.

## Adding a relay manually

1. Open **Relay Management**.
2. Enter the relay URL.
3. Choose read/write settings.
4. Add the relay.
5. Save the relay list.

## Saving relay changes

Saving relay changes publishes relay metadata for the active key.

Before saving:

- check active account
- remove dead or unwanted relays
- avoid excessive relay counts
- confirm read/write settings are right.

## How relay settings affect other features

Relay configuration affects:

- profile publishing
- Quick Publish
- visibility of signed events
- how other Nostr clients discover your preferred relays.

NIP-47 wallet connections use their own relays from the NWC URI and are managed in **Wallet Management**, not Relay Management.

## Common issues

### Invalid relay URL

The URL must start with `ws://` or `wss://`.

### Relay list save failed

Possible causes:

- vault is locked
- no active key
- signing failed
- relays are unreachable
- network error.

### Events are not visible in other clients

Check that:

- you published to relays other clients read from
- your relay metadata was saved
- the target client has refreshed
- relays did not reject your event.

### Relay browser returns no results

Try changing the search query, disabling filters, or refreshing the catalog.

## Best practices

- Prefer stable `wss://` relays.
- Keep the list small.
- Use known relays for important identities.
- Periodically remove dead relays.
- Save relay metadata after changes.
- Keep 1 to 3 Direct Message Relays that keep private messages.
