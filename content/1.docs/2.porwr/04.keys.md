This is one of the most sensitive areas of Porwr. A Nostr private key controls an identity. Anyone with that private key can act as that identity.

## What Key Management is for

Use Key Management to:

- create a new Nostr identity
- import an existing Nostr private key
- view stored keys
- rename local key aliases
- select which identity is active
- export a backup of a single key
- back up or restore the whole vault
- inspect public/private key details when needed.

## Nostr keys in plain English

A Nostr identity has two important parts:

- **Public key** — identifies you publicly. Safe to share.
- **Private key** — controls the identity. Never share it.

Public keys are often encoded as `npub...`.

Private keys are often encoded as `nsec...`.

Porwr stores private keys in an encrypted local vault so websites can request signatures without receiving your private key.

## Active key

The active key is the identity Porwr uses by default.

It is used for:

- NIP-07 website signing
- profile updates
- relay metadata publishing
- Quick Publish.

If you manage multiple identities, check the active key before signing or publishing.

## Creating a new key

Use **Add New Key** when you want a fresh Nostr identity.

Typical workflow:

1. Open **Key Management**.
2. Choose **Add New Key**.
3. Enter a local alias.
4. Generate the key.
5. Save it to the vault.
6. Make a [vault backup](#vault-backup) and store it securely.

The alias is local to Porwr. It does not change your Nostr public key or public profile name.

## Importing an existing key

Use **Import Key** when you already have a Nostr private key.

Typical workflow:

1. Open **Key Management**.
2. Choose **Import Key**.
3. Paste the `nsec...` private key.
4. Add a recognizable alias.
5. Save it into the vault.

Only import keys on devices you control and trust.

## Viewing a key

The key view lets you inspect a stored key, change its local alias, and [export it](#exporting-a-single-key).

Be careful when viewing private key material. Do not screen-share, screenshot, or paste private keys into chat.

## Local aliases

Aliases help you recognize keys inside Porwr.

Examples:

- `Main Account`
- `Work`
- `Personal`
- `Testing`
- `Anonymous`

Aliases are not public Nostr names. To change your public name, use **Profile Management**.

## Vault Backup & Restore

The **Vault Backup & Restore** card on the Key Management page has two buttons:

- **Backup** creates an encrypted backup of your vault.
- **Restore** replaces your vault with one from an encrypted backup.

Each opens its own page with the details and warnings you need before you go ahead.

![The Vault Backup & Restore card on the Key Management page, with its Backup and Restore buttons](/img/screenshots/porwr/vault-backup-restore.png)

### Vault Backup

A vault backup is an encrypted copy of your entire vault: your keys, accounts and settings. Make one after you create or import an important key, and again after you add an important wallet connection.

1. Open **Key Management**.
2. In **Vault Backup & Restore**, choose **Backup**.
3. Read the notes on the **Vault Backup** page.
4. Choose **Backup**, then choose where to save the file.

Porwr confirms when the backup is saved and shows where. If you close the save window, nothing is written.

Before you rely on a backup:

- The backup opens only with the vault password you have when you make it. Write that password down: Porwr cannot remind you of it.
- If the password is lost, nobody can open the backup, Diogel support included.
- Keep the backup somewhere safe, ideally offline.
- Never keep the backup in the same place as its password.

### Vault Restore

Restoring replaces your current vault with the one in a backup. Everything in your current vault is erased: its keys, accounts and stored settings. Back up your current vault first so you don't lose anything.

1. Open **Key Management**.
2. In **Vault Backup & Restore**, choose **Restore**.
3. Read the warnings on the **Vault Restore** page.
4. Choose the **Backup file**, a `.json` vault backup made by Porwr.
5. Enter the **Backup's password**. This is the vault password from when the backup was made, which may not be your current password.
6. Choose **Restore**.

When the restore finishes, unlock Porwr with the backup's password.

![The Vault Restore page with its warnings, the backup file picker and the backup's password field](/img/screenshots/porwr/vault-restore.png)

If the restore fails, Porwr tells you why and your current vault is not changed:

- **This file is not a Porwr vault backup, or it is damaged.** Choose the right file. Porwr only restores its own vault backups.
- **That password does not open this backup.** Use the vault password from when the backup was made.
- **The backup could not be restored.** Try again. If it keeps failing, check that the browser can store extension data.

### Vault password

Your vault password is not a cloud account password.

Porwr cannot reset it for you. If you forget it and have no usable backup or private key export, you may lose access to stored identities.

### Relationship to browser sync

Do not rely on browser sync as your only backup strategy.

Browser extension storage behavior can vary by browser, profile, and extension settings. Use a Porwr vault backup for intentional backups.

## Exporting a single key

To back up one key instead of the whole vault, open the key and choose **Export**.

1. Enter your vault password.
2. Choose and confirm a password for the backup.
3. Enter a file name and choose **Export**.

Porwr saves the key encrypted with that password, as a NIP-49 `ncryptsec`. Porwr and other Nostr clients can import it. Keep the password: without it the backup cannot be opened.

Store backups in a secure place, such as:

- a reputable password manager
- an encrypted offline drive
- a printed/offline recovery record stored safely.

Avoid storing raw private keys in plain text files or cloud notes.

## Multiple identities

Porwr can store multiple identities in the vault.

This is useful for separating contexts:

- personal identity
- work identity
- testing identity
- anonymous or pseudonymous identity.

Before signing from a website or publishing, confirm the active identity is the one you intend to use.

## Security warnings

### Never share your private key

Your private key controls your identity. If someone gets it, they can impersonate you.

### Do not paste private keys into websites

A website that asks for an `nsec` key should be treated with suspicion. Use Porwr as a signer instead.

### Back up before relying on an identity

If the browser profile is lost, corrupted, or deleted, you may lose local vault data unless you have a [vault backup](#vault-backup).

### Keep your vault password safe

The vault password protects local encrypted vault data. Porwr cannot reset it if forgotten.

## Common issues

### Invalid nsec

The imported private key must be a valid Nostr private key. Check that it starts with `nsec` and was copied completely.

### Duplicate key

Porwr may reject importing a key that already exists in the vault.

### No active account selected

Open Key Management and select the key you want to use.

### Website signs with the wrong identity

Check the active key before approving website requests.

## Best practices

- Use clear aliases.
- Make a vault backup after creating or importing important keys, and after adding important wallet connections.
- Back up your current vault before restoring another one.
- Keep backups and their passwords in separate, secure places.
- Do not expose private keys during screenshots or support requests.
- Use separate identities for separate contexts.
- Check active identity before approving signatures.
