## What is Bancwr

Bancwr is a self-hosted Nostr bunker for teams. A bunker is a server that holds a key and signs on request, so the key never leaves it. Bancwr speaks NIP-46, the Nostr standard for remote signing: Nostr apps connect to it and ask it to sign events.

You run Bancwr on your own server. It has two parts:

- The bunker, which holds the signing keys and answers NIP-46 requests over Nostr relays.
- The console, a web dashboard where your team signs in and manages the bunker.

With Bancwr you can:

- Keep your brand's Nostr keys on a server you control, encrypted at rest.
- Sign as more than one identity from one bunker.
- Give team members access with their own Nostr keys, as an admin, a signer or a viewer.
- Connect Nostr apps with single-use connection tokens, each limited to the event kinds you choose.
- Hold the kinds you choose for an administrator's approval before anything is signed.
- Give connections a time limit and a rate limit, and revoke them at any time.
- Keep a log of every signature and every change to who may sign, and export it.
- Back up and restore the bunker with encrypted archives.

## Core concepts

### The bunker's key

The bunker signs with its own key, never a team member's. You import that key once, when you install Bancwr, and it stays on the server.

- The key is encrypted at rest in `./data/bunker-key.enc`, under a root credential kept in `./secrets`. A copy of `./data` on its own does not reveal the key.
- The bunker never reads a plain key while it runs. If one is still configured, it stays locked and signs nothing.
- The console never shows a private key, and there is no way to export one.

Anyone who controls the server can still read both files, or the bunker's memory, and so the key. See [Protecting the bunker key](/docs/bancwr/protecting-the-key).

### Several identities in one bunker

One bunker can sign as several Nostr keys, its identities, so an agency or a brand with several accounts needs one bunker, not one per key. The first key you import is the primary.

Each connection token is issued for one identity, and its app signs only as that identity. Administrators grant each member the identities they may sign as. See [Signing identities](/docs/bancwr/signing-identities).

### Team members sign in with their own key

People sign in to the console with their own Nostr key, through:

- a Nostr browser extension (NIP-07), such as Porwr, or
- a remote signer (NIP-46), by pasting its `bunker://` connection string.

Bancwr never asks for a private key. There is no field for an `nsec`.

Only keys registered with the bunker can use the console. An administrator registers them on the **Team** page.

### Roles

Each team member has one of three roles: Admin, Signer or Viewer.

| Page | Admin | Signer | Viewer |
|------|:---:|:---:|:---:|
| Dashboard | Metrics, health and everyone's activity | Health, their connected apps and their own signatures | Health, and a link to the team |
| Team | Add and remove members, change roles | | Read-only |
| A member's profile | Yes | | Yes |
| Config | Yes | | |
| Logs | Yes, with export | | |
| Connections | All apps, and issuing tokens | Their own apps | |
| Approvals | All requests, and deciding them | Their own requests, to see | |
| Profile, Follows, Relays | Yes | Yes | |

- An admin manages the bunker: the team, identities, connection tokens, approvals, the bunker's relays and the signing log. An admin can do everything a signer and a viewer can.
- A signer has apps connected for them, sees their own signatures, and edits their own Nostr profile, follows and relays.
- A viewer sees the bunker's health and the team, read-only. A viewer never holds an app connection.

The sidebar only shows the pages your role can open. If you open a page your role does not allow, Bancwr shows a permission-denied page. The bunker checks the same rules itself on every request.

### Apps sign only what you allow

An app connects only with a connection token an administrator issues. The token names the member it is for, the identity it signs as, and the event kinds it may sign. There is no "sign everything" option. A token can also allow encrypting and decrypting messages, set how long the connection lasts and how fast it may sign. See [Connecting apps](/docs/bancwr/connecting-apps).

### Approval before signing

A token can mark some of its kinds as needing approval. A request to sign one of them waits under **Approvals**, showing the event exactly as it will be signed, until an administrator approves or rejects it. See [Approval before signing](/docs/bancwr/approval-before-signing).

### Signed images

Each release's container images are signed, and carry signed build provenance and a software bill of materials (SBOM), made by Bancwr's release workflow. You can check them with `cosign` and the GitHub CLI before you deploy. See [Verify the images](/docs/bancwr/installation#verify-the-images-optional).

## What Bancwr is not

Bancwr is not a custodial service for your personal keys. Team members keep their own keys in their own signer. Bancwr only knows their public keys.

Bancwr is not a relay. It connects to the relays you choose to receive and answer NIP-46 requests, and the console reads and publishes members' profiles through Nostr relays.

## How Bancwr relates to Porwr and Symudol

Bancwr is part of the Diogel suite:

- [Porwr](/docs/porwr) is a browser extension signer (NIP-07). It keeps your keys in your browser.
- [Symudol](/docs/symudol) is the Diogel signer for your mobile.
- Bancwr is a signer that runs on a server and is shared by a team.

You can use Porwr to sign in to the Bancwr console with your own key.
